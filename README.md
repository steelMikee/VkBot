# VK Vacancy Bot

Автоматический бот для поиска вакансий через VK с использованием API trudvsem.ru.  
Создайте заявку с фильтрами — бот будет искать вакансии по расписанию и присылать уведомления прямо в личку.

> **Возможности:** поиск по 95 регионам РФ • виртуальные потоки Java 21 • интерактивные кнопки • периодические уведомления • LRU-кэш • атомарное хранение данных • Docker-развёртывание

## ✨ Ключевые особенности

* **Реализация на Core Java &#40;JDK 21&#41;:** Бизнес-логика и управление состояниями реализованы стандартными средствами JDK без фреймворков и баз данных. Для интеграций подключены только точечные библиотеки (VK SDK, Jackson, SLF4J), а стабильность кода подтверждена unit- и интеграционными тестами (JUnit, Mockito, WireMock).

* **Параллельный поиск по всей России (Virtual Threads):** При широком поиске бот одновременно опрашивает все 95 регионов через виртуальные потоки Java 21, эффективно утилизируя сетевые I/O-ожидания — результат приходит за секунды вместо минут.

* **Умный подбор и ранжирование вакансий:** Многоступенчатая фильтрация по региону, опыту, ключевым словам и уровню дохода с интеллектуальной сортировкой — наиболее релевантные предложения, близкие к вашему целевому диапазону зарплаты, оказываются наверху.

* **Интерактивный диалог (State-machine):** Пошаговая навигация через Reply- и Inline-клавиатуры VK — постраничный выбор региона (пагинация), настройка фильтров, черновики при редактировании, а также быстрые кнопки «Изменить» и «Удалить» прямо под каждой задачей.

* **Автономная работа 24/7:** Состояние планировщика и активные подписки автоматически восстанавливаются после перезапуска — бот «помнит» все задачи и продолжает уведомлять вас о новых вакансиях по расписанию.

* **Безопасное хранение данных:** Атомарная запись состояния в JSON через временные файлы. Паттерн *write-temp-and-rename* гарантирует целостность данных и защищает их от повреждения даже при сбоях или внезапном отключении питания.

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/steelMikee/VkBot
cd VkBot
```

### 2. Создайте `.env`

```properties
VK_GROUP_ID=ваш_id_группы
VK_ACCESS_TOKEN=ваш_long_poll_токен
DATA_DIR=data
NOTIFICATION_PERIOD_HOURS=24
SCHEDULER_INITIAL_DELAY_MINUTES=1
```

| Переменная | Описание | По умолчанию |
|---|---|---|
| `VK_GROUP_ID` | ID группы VK | обязательно |
| `VK_ACCESS_TOKEN` | Long Poll токен | обязательно |
| `DATA_DIR` | Папка данных | `data` |
| `NOTIFICATION_PERIOD_HOURS` | Интервал поиска (часы) | `24` |
| `SCHEDULER_INITIAL_DELAY_MINUTES` | Задержка первого запуска | `1` |

### 3. Запустите

```bash
./gradlew.bat run
```

### Альтернатива — Docker
Бот запустится в контейнере, данные сохранятся в папке `./data` на хосте.

```bash
docker compose up --build -d
```

### Проверьте логи:
```bash
docker logs -f vk-vacancy-bot
```

### В конце сесси Выйдите(ctrl+c) из логов бота в терминале и Удалите контейнер: 
```bash
docker rm -f vk-vacancy-bot
```

<summary>✨ Особенности реализации</summary>

**Виртуальные потоки (Virtual Threads):**

- Поиск по всем 95 регионам выполняется параллельно через `Executors.newVirtualThreadPerTaskExecutor()` — 95 лёгких потоков вместо тяжёлых OS-потоков, что позволяет масштабироваться до тысяч одновременных запросов без переполнения памяти.
- Каждая заявка на поиск запускается в отдельном виртуальном потоке (`Thread.ofVirtual()`), чтобы пользователь не ждал ответа.

**Умная фильтрация и сортировка вакансий:**

- **Многоступенчатая фильтрация** — `VacancyMatcher` последовательно проверяет опыт, зарплату, регион и ключевые слова. При фильтрации по зарплате учитываются диапазоны: если указана только нижняя граница, вакансия с `salaryMin = 0`, но подходящим `salaryMax` не отбрасывается преждевременно.
- **Интеллектуальная сортировка** — `VacancySorter` вычисляет «идеальный центр» зарплатного диапазона и сортирует вакансии по близости к нему. Вакансии без указания зарплаты всегда уходят в конец списка.
- **Широкий поиск с лимитом** — при поиске по всем регионам бот собирает до 1000 вакансий, отменяя ожидающие запросы, как только лимит достигнут.

**Интерактивный диалог с навигацией по экранам:**

- **Диалоговые состояния** — каждый пользователь имеет состояние (`DialogState`), которое определяет, как интерпретировать его сообщение. Это позволяет боту понимать контекст: ожидает ли он ввод региона, опыта или зарплаты.
- **Интерактивные клавиатуры** — `KeyboardBuilder` генерирует JSON-клавиатуры VK с кнопками разных цветов (positive, primary, negative). Inline-кнопки «Изменить» и «Удалить» привязаны к конкретной задаче через JSON-payload.
- **Динамическая маршрутизация** — `DynamicHandlerRegistrar` регистрирует обработчики, которые срабатывают в зависимости от диалогового состояния и текста сообщения. Например, в состоянии ожидания региона бот распознаёт кнопки меню, варианты опыта, зарплатные диапазоны и свободный текст.
- **Справочник 95 регионов** — `RegionDirectory` содержит все регионы РФ с кодами, поддерживает пагинацию по 3 региона на страницу и умный поиск по токенам с толерантностью к частичным совпадениям и шумовым словам («область», «республика», «край»).

**Конкурентность и кэширование:**

- **LRU-кэш пользователей** на `ConcurrentHashMap` + `ConcurrentLinkedDeque` с `ReentrantLock` — кэширует до 1000 последних активных пользователей, минимизируя обращения к диску.
- **`ScheduledExecutorService`** с пулом из 4 потоков — планирование периодического поиска вакансий с автоматическим восстановлением задач при перезапуске.
- **Graceful shutdown** — при остановке приложения `shutdown-hook` корректно завершает планировщик с таймаутом 5 секунд, а Long Poll-цикл обрабатывает `InterruptedException`.

**Архитектура:**

- **Слоённая архитектура** — чёткое разделение: Command → Service → Repository → Client → Model
- **Strategy паттерн** — каждая команда бота реализует `BotCommand`, диспетчер маршрутизирует по `CommandType` через `EnumMap`
- **Атомарная запись JSON** — репозитории пишут в `.tmp` файл, затем атомарно переименовывают через `StandardCopyOption.ATOMIC_MOVE` с fallback на обычный `REPLACE_EXISTING`, исключая повреждение данных
- **Lombok** — `@Getter`, `@Slf4j`, `@NoArgsConstructor` сокращают шаблонный код на 30-40%

**Надёжность:**

- Персистентность через JSON-файлы — данные выживают после перезапуска
- Команда `/stop` корректно завершает задачи и очищает данные
- Валидация `.env` при старте — бот не запускается без обязательных токенов
- Чанкирование длинных сообщений — `sendChunked()` разбивает списки вакансий на части по 4000 символов (лимит VK)
- Long Poll с автоматическим переподключением — при ошибках сервера бот получает новый session key и продолжает работу
- Изоляция `.env` при запуске тестов — Gradle автоматически переименовывает `.env` в `.env.backup` перед тестами и возвращает обратно

**Java 21 возможности:**

- **`record`** — неизменяемые DTO (`IncomingMessage`, `RawVacancy`, `LongPollSession`, `Region`, `RegionPage`) без boilerplate-кода
- **Pattern matching for `instanceof`** — безопасное приведение типов без явных кастов
- **Text blocks** — многострочные строки для форматирования сообщений бота
- **Switch expressions** — компактная маршрутизация команд через `CommandType` и обработка Long Poll ошибок
